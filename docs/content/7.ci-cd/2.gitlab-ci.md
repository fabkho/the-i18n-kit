The template lives at the repository root as `gitlab-ci.yml` and defines three
hidden jobs you extend. Each installs `@the-i18n-kit/cli` and runs one command:
`.i18n-translate` commits and pushes translated locale files, `.i18n-cleanup`
reports orphan keys, and `.i18n-check` reports keys that render as their raw key.
Only the first writes to your repository.

## Including the Template

```yaml [.gitlab-ci.yml]
include:
  - remote: 'https://raw.githubusercontent.com/fabkho/the-i18n-kit/main/gitlab-ci.yml'

stages:
  - lint

i18n-check:
  extends: .i18n-check
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
```

- **Declare a `lint` stage.** All three jobs set `stage: lint`, and GitLab rejects
  the pipeline configuration when a job names a stage that does not exist.
- **Pin the template.** The URL tracks `main`. Replace it with a release tag, and
  pin the CLI alongside it with `I18N_CLI_VERSION`.

Every job decides its outcome from the CLI's
[exit code](/getting-started/agent-contract#exit-codes). `.i18n-cleanup` and
`.i18n-check` carry `allow_failure.exit_codes: [2]`, so findings show as a yellow
warning that still reaches the merge request widget while a scan that fell over
fails red. Set `allow_failure: false` on your extending job to make findings block
the merge.

::warning
`allow_failure.exit_codes` applies to the whole job, `before_script` included,
which is why the setup lines in those two jobs end in `|| exit 1`. An installer
that exits `2` would otherwise pass the job yellow having run no scan.
::

## `.i18n-translate`

Translates missing keys, commits the changed locale files and pushes them to the
branch that triggered the pipeline.

```yaml [.gitlab-ci.yml]
i18n-translate:
  extends: .i18n-translate
  variables:
    I18N_PROVIDER: google
    I18N_MODEL: gemini-2.5-flash
    I18N_API_KEY: $GEMINI_API_KEY
    I18N_LOCALE_PATHS: "i18n/locales/ app-*/i18n/locales/"
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
      changes: ['i18n/locales/en.json']
```

`I18N_PROVIDER`, `I18N_MODEL` and `I18N_API_KEY` are required; the script exits
`1` up front naming the ones that are unset.

| Variable | Default | Description |
|---|---|---|
| `I18N_LAYER` | *(all layers)* | Empty translates every locale-backed layer in one run and one commit |
| `I18N_LOCALES`, `I18N_SOURCE_LOCALE`, `I18N_KEYS` | *(all)* | Target locales, reference locale, key subset |
| `I18N_BATCH_SIZE` | `50` | Keys per LLM call |
| `I18N_DRY_RUN` | `false` | `"true"` previews without writing or committing |
| `I18N_FAIL_ON_FAILED` | *(off)* | `"true"` exits `2` when any key failed |
| `I18N_LOCALE_PATHS` | `i18n/locales/` | Space-separated globs the job stages and commits |
| `I18N_COMMIT_MESSAGE` | *(generated)* | Replaces the default commit message |
| `I18N_PUSH_TOKEN` | *(empty)* | Token used for the push instead of the job token |
| `I18N_CLI_VERSION`, `I18N_INSTALL_PEER_DEPS` | `latest`, *(empty)* | CLI version, extra packages |

::warning
`I18N_LOCALE_PATHS` is what the job stages. On a layered project with an empty
`I18N_LAYER` it must cover every layer's locale directory, or the translations for
the layers it misses are written on the runner and never committed — the job
reports a clean run and the keys are still missing on the next one.
::

The job carries `allow_failure: true`, so nothing it does blocks a merge by
default. A gate trips only after the commit and push, so a red job never costs you
the translations. The raw result is kept as `.i18n-reports/translate-output.json`.

**Letting it push.** A CI token has no write access unless you grant it. Either
turn on Settings → CI/CD → Job token permissions → *Allow Git push requests to the
repository* (GitLab 17.2+), or pass a project access token with `write_repository`
as `I18N_PUSH_TOKEN`. Add the `api` scope: it lets the job trigger a pipeline at
the new head, which is what keeps the Code Quality widget alive after an
auto-commit.

## `.i18n-cleanup` and `.i18n-check`

`.i18n-cleanup` reports [orphan keys](/monorepos/orphan-detection) and deletes
nothing. `I18N_FAIL_ON_ORPHANS: "true"` makes orphans trip a gate; without it they
stay informational. `.i18n-check`'s gate is always evaluated — there is nothing to
opt into. Both take `I18N_LAYER`, `I18N_CLI_VERSION` and `I18N_INSTALL_PEER_DEPS`,
and keep their report plus `gl-codequality.json` as artifacts for 7 days.

## The Code Quality Widget

Both scan jobs declare `gl-codequality.json` under `artifacts:reports:codequality`.
GitLab renders it as a **diff** against the newest default-branch report.

::warning
The diff needs both sides. A job that runs only on merge requests has no baseline,
so **the widget stays blank**. Every job you adopt needs a second rule that runs it
on the default branch, and that rule must carry no `changes:` filter — a filtered
baseline is skipped whenever the last merge happened not to touch those paths.
::

```yaml [.gitlab-ci.yml]
i18n-cleanup:
  extends: .i18n-cleanup
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
      changes: ['components/**/*.vue', 'i18n/locales/*.json']
    # Baseline. No `changes:` filter, or the widget goes blank on the next MR.
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
```

Baselines expire with the artifacts after 7 days, so on a quiet default branch the
widget goes blank until the next default-branch pipeline. Raise `expire_in` if
that describes your project.

## Overriding the Jobs

`image`, `before_script`, `tags` and `cache` are overridable on the extending job
— the supported path for private registries and self-hosted mirrors. To add
packages without replacing anything, use `I18N_INSTALL_PEER_DEPS`.

A replacement `before_script` must keep putting `the-i18n-cli` on the `PATH`, keep
the `|| exit 1` on the two scan jobs, and install `jq` (both scan jobs and
translate), `git` (translate) and the provider SDK — `openai`,
`@anthropic-ai/sdk` or `@google/genai`, which are optional peer dependencies.
Keep replacement scripts POSIX `sh`: `dash` aborts a job before running a line on
`set -o pipefail`.
