The React adapter covers Next.js and plain React projects, in both the namespaced (`messages/en/common.json`) and flat (`locales/en.json`) layouts. Where the project already declares its locales — next-intl routing, next-translate, or the Pages Router `i18n` block — it executes that file and reads the declaration.

A **layer** is a scoped locale directory: a Nuxt layer, a workspace package, a shared UI library, or one app in a monorepo. A React project resolves as a single layer named `root`.

A project is recognized by `next`, or by `react` and `react-dom`, in `dependencies` or `devDependencies`. A project carrying `vue`, `nuxt` or `@nuxt/kit`, or a `nuxt.config.{ts,js,mjs}`, is not this adapter's project however much React is in it.

## Locale Directories Probed

Resolution asks `next.config` first and falls back to convention:

1. **`next.config.{ts,js,mjs}`, read as text.** `createNextIntlPlugin` pins the directory to `messages/`, and `next-translate` pins it to `locales/`, when that directory exists. Otherwise the first `messages:`, `localeDir:` or `locales:` string literal is taken as a path, trailing `/*` and `/*/*` trimmed, and used if it exists.
2. **Conventional directories**, first match wins: `messages`, `public/locales`, `locales`, `src/i18n`, `src/locales`, `i18n`.

One directory is used. Inside it, both layouts are recognized:

| Layout | Looks like | Locale codes come from |
|---|---|---|
| Namespaced | `messages/en/common.json` | Subdirectory names, when any subdirectory holds `.json` files |
| Flat | `locales/en.json` | File base names |

Namespaced wins where both are present. `node_modules`, `.git`, `.DS_Store` and dot-entries are skipped. If no directory is found, or a directory is found with neither layout in it, the command fails naming what it looked for.

## What Is Derived, and From Which File

Three setups declare the locales authoritatively. Each is executed, and the first that yields something wins:

| Order | Setup | File | Gives |
|---|---|---|---|
| 1 | next-intl | `src/i18n/routing.{ts,js}` or `i18n/routing.{ts,js}` | `defaultLocale`, `locales` |
| 2 | next-translate | `i18n.{js,ts,mjs}` | `defaultLocale`, `locales` |
| 3 | Pages Router | `next.config.{ts,js,mjs}` — the `i18n` block | `defaultLocale`, `locales` |

The adapter takes **`defaultLocale`** from whichever source answered. The locale list itself still comes from the directory, so a locale declared in routing but absent from `messages/` is not invented.

A routing file works whether it exports `routing` by name or as its default, and a `next.config` exported as a function is called the way Next.js calls it, including an async one. A routing file with `next-intl` not installed — a fresh clone, a CI job that skipped install — is still read.

## Layers

One, named `root`. The whole project is a single locale directory as far as this adapter is concerned; a monorepo of React apps that each need their own layer is served by the [generic adapter](/frameworks/generic), where each path carries its own layer name.

## Overrides

| What you want | How |
|---|---|
| Set the default locale regardless of framework config | `defaultLocale` — wins over every derived source |
| Restrict or reorder the locale list | `locales` |
| Force this adapter | `framework: 'react'` |
| Name the directories yourself, or split them into layers | `localeDirs` + `defaultLocale`, which hands the project to the [generic adapter](/frameworks/generic) |

```ts [i18n-kit.config.ts]
import { defineI18nKitConfig } from '@the-i18n-kit/cli/config'

export default defineI18nKitConfig({
  defaultLocale: 'en',
})
```

## Limits

- **A `next.config.js` wrapped in `withNextIntl(...)`, `withSentryConfig(...)` or anything else may fail to execute** — those wrappers need their packages installed and their environment present. That is never fatal: the CLI warns, naming the file and the error, and falls back to the directory probing above. It is also why the fallback still exists.
- When nothing declares a default locale and none is configured, the fallback is the first locale code in sorted order — the alphabet, not a decision, and silent. Declaring `defaultLocale` removes the question.
- Only one locale directory is used. A project keeping messages in two places needs the generic adapter.
- A routing file that exports something other than an object, or declares neither `locales` nor `defaultLocale`, is skipped in favor of the next source.
