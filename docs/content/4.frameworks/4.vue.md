The Vue adapter resolves a Vue 3 SPA — anything using `vue-i18n` outside Nuxt. Where your Vite config already declares where the messages live, it executes that config and reads the answer; otherwise it probes a list of conventional directories.

A **layer** is a scoped locale directory: a Nuxt layer, a workspace package, a shared UI library, or one app in a monorepo. A Vue project gets one layer per locale directory.

A Nuxt app is never a Vue app here, however much Vue is in it: a project carrying `nuxt` or `@nuxt/kit`, or a `nuxt.config.{ts,js,mjs}`, belongs to the [Nuxt adapter](/frameworks/nuxt).

## Locale Directories Probed

Resolution asks the project first and falls back to convention:

1. **`vite.config.{ts,js,mts,mjs}`** — executed, with `@intlify/unplugin-vue-i18n` substituted by a recorder. Every existing directory named by the plugin's `include` becomes a locale directory. This is the authoritative answer: `include` *is* where the locale files are, by definition.
2. **A path pattern-matched out of an i18n module** — the first of `src/i18n/index.{ts,js}`, `src/plugins/i18n.{ts,js}`, `src/i18n.{ts,js}` and `i18n.{ts,js}` that exists is read as text. A `localeDir:` string literal is resolved against the project root; a `messages:` string literal is resolved against that module's own directory and reduced to its parent directory. Either is used only if the result exists on disk.
3. **Conventional directories**, first match wins: `src/locales`, `locales`, `src/i18n/locales`, `i18n/locales`, `src/plugins/i18n/locales`, `src/i18n`.

If none of the three yields a directory, the command fails listing the conventional candidates and pointing at `localeDirs`.

Locales are the `.json` file names across every resolved directory, unioned. When two directories define the same code, the first one to define it owns the file name and the rest contribute their keys to it, the way a layer does.

## What Is Derived, and From Which File

| Source | Read how | Gives |
|---|---|---|
| `vite.config.{ts,js,mts,mjs}` | Executed with `@intlify/unplugin-vue-i18n` aliased to a recorder | The locale directories, from the plugin's `include` |

Both config forms work: a plain exported object, and `defineConfig(({ mode }) => ({ ... }))`. Every specifier the plugin ships under — `/vite`, `/rollup`, `/webpack` and the bare package — is recognized.

Each `include` entry is treated as a glob and reduced to everything before its first wildcard, so `resolve(__dirname, './src/locales/**')` yields `src/locales`. Every entry is kept, not only the first, so messages split across directories are all found. Entries naming a directory that does not exist are ignored.

::note
The default locale is not derived here. `include` says where the files are, not which one is the source. Declare `defaultLocale` yourself — see below.
::

## Layers

One locale directory resolves to a single layer named `root`, which is the shape a Vue SPA has always had.

Several `include` roots resolve to one layer per directory, named after the directory. When two share a name, the parent segment is prefixed to tell them apart: `./src/messages/**` and `./src/admin/messages/**` become the layers `src/messages` and `admin/messages`.

## Overrides

| What you want | How |
|---|---|
| Set the default locale | `defaultLocale` — always wins over discovery |
| Restrict or reorder the locale list | `locales` |
| Force this adapter | `framework: 'vue'` |
| Name the directories yourself | `localeDirs` + `defaultLocale`, which hands the project to the [generic adapter](/frameworks/generic) |

```ts [i18n-kit.config.ts]
import { defineI18nKitConfig } from '@the-i18n-kit/cli/config'

export default defineI18nKitConfig({
  defaultLocale: 'en',
})
```

## Limits

- **Nothing tells this adapter your default locale.** With no `defaultLocale` declared, it falls back to the first discovered locale code in sorted order, which is the alphabet rather than a decision — `de` beats `en` in a `{de,en,fr}.json` project. One line of config removes the guess, and it is the line worth writing.
- A `vite.config.ts` that throws — a plugin not installed, an environment variable it needs — is a warning and a fall back to the probing above, never a failed command. The warning names the file and suggests declaring the value instead.
- Each Vite config is executed once per process and its answer remembered. Editing the config during a long-running MCP session does not change the answer; restart it.
- The pattern-matching fallback reads one string literal. A `messages` path assembled from variables is not seen.
