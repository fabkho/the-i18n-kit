title: Nuxt
description: How the Nuxt adapter recognizes an app, resolves every layer's locale directory, and what it reads out of nuxt.config.

The Nuxt adapter resolves your locales from what Nuxt itself resolved — every layer, every app in the monorepo, with the locale table `@nuxtjs/i18n` produced rather than a reconstruction of it. This page covers what it recognizes, where it looks, and what you can override.

A **layer** here is a scoped locale directory: a Nuxt layer, a workspace package, a shared UI library, or one app in a monorepo. Nuxt is the framework where the kit's layer model came from, so the adapter maps Nuxt's `_layers` onto it directly.

## How Detection Recognizes the Project

| Signal | Score |
|---|---|
| A `nuxt.config.{ts,js,mjs}` at the project root whose contents mention `i18n` | 2 |
| No root config, but a child directory holds a Nuxt config that mentions `i18n` | 2 |
| A root Nuxt config that mentions no `i18n`, with no child app that does | 1 |
| No Nuxt config anywhere under the root | 0 |

The child scan walks up to four directories deep, skipping `node_modules`, `.nuxt`, `.output`, `.git`, `dist`, `.cache` and any dot-directory. A directory qualifies as an app when it has a Nuxt config whose text matches `i18n`.

Two is a low ceiling and it never costs Nuxt a project: the Vue and React adapters both score 0 the moment `nuxt` or `@nuxt/kit` is a dependency, or a `nuxt.config` file exists. See [Detection](/frameworks/detection) for the full ranking.

## Locale Directories Probed

None — the adapter does not guess from a candidate list. Each layer contributes exactly one directory, resolved as:

```
<layerRootDir>/<restructureDir>/<langDir>
```

`restructureDir` defaults to `i18n` and `langDir` defaults to `locales`, so an untouched Nuxt 4 project resolves to `i18n/locales/` per layer. A layer that sets either option in its own `i18n` block is honored with its own values.

A resolved directory is skipped, with a debug line saying so, when it does not exist or contains no `.json` files. Directories that resolve to the same real path through a symlink are claimed once, so a linked layer does not appear twice.

If no layer yields a locale directory, the command fails rather than reporting an empty project.

## What Is Derived, and From Which File

| Source | Read when | Gives |
|---|---|---|
| `.nuxt/i18n-kit.json` | `@the-i18n-kit/nuxt` is installed and the app has been built | `defaultLocale`, `fallbackLocale`, the locale table (`code`, `language`, `file`, `name`), and every layer's root and locale directory — see [What It Publishes](/nuxt-module/what-it-publishes) |
| `nuxt.config.{ts,js,mjs}`, loaded through Nuxt | No usable artifact | The same `i18n` options and `_layers`, resolved by loading the app |

The artifact is the faster and more faithful path: `@the-i18n-kit/nuxt` publishes what Nuxt resolved from inside the build, so module-injected layers and computed locale arrays are already flattened. It is additive — an absent, malformed, unknown-version or stale artifact falls through to loading the app, and an artifact describing no locale directory is logged and discarded in favor of loading. A project without the module behaves exactly as it always has.

Without an artifact, the adapter calls `loadNuxt` from the project's **own** `@nuxt/kit`, with logging silenced. A first failure is retried with `ready: false` before the command gives up. `@nuxt/kit` therefore has to be installed; when it is missing, the error says so and names the install command.

In a monorepo, every discovered app is loaded and merged. An app that fails to load is logged as a warning and skipped rather than failing the run — a repository where one app cannot build still has translations worth managing.

## Layers

Layer names come from each layer's root directory relative to the discovery root: the root itself is `root`, and anything else takes its directory name. When two layers would collide, parent segments are prefixed until they differ (`admin`, then `apps/admin`). The same naming is applied to app names, so `--layer` and the per-app usage evidence line up with the paths you already know.

## Overrides

| What you want | How |
|---|---|
| Restrict or reorder the locale list | `locales` in `i18n-kit.config.ts` or `.i18n-mcp.json` — codes with no discovered entry are kept with a warning, discovered codes not listed are dropped |
| Force this adapter | `framework: 'nuxt'` |
| Authoring context, glossary, protected locales | `i18n-kit.config.ts` or `.i18n-mcp.json`. Not `nuxt.config.ts` — `@the-i18n-kit/nuxt` carries no policy |

```ts [i18n-kit.config.ts]
import { defineI18nKitConfig } from '@the-i18n-kit/cli/config'

export default defineI18nKitConfig({
  locales: ['en', 'de', 'fr'],
  protectedLocales: ['de-formal'],
})
```

::warning
A `defaultLocale` declared in `i18n-kit.config.ts` or `.i18n-mcp.json` is **not** consulted by this adapter. The default locale comes from `i18n.defaultLocale` in `nuxt.config.ts` (or the artifact that mirrors it), falling back to `en` when the block sets none. Change it in the Nuxt config, which is where Nuxt itself reads it.
::

## Limits

- Resolution needs the app to load. A `nuxt.config.ts` that throws without environment variables the CLI does not have fails for this adapter the way it would for `nuxt build` — install `@the-i18n-kit/nuxt` and commit its artifact path to your build if that is a problem in CI.
- The artifact carries no kit policy, and `nuxt.config.ts` is not a place to declare any. Policy — `protectedLocales` above all — belongs in `i18n-kit.config.ts` or `.i18n-mcp.json`, which are read from disk with no build step.
- A Nuxt config with no `i18n` block is an error naming the app, not an empty result.
- Locale entries without both a `code` and a `file` are dropped; if none survive, the command fails.
