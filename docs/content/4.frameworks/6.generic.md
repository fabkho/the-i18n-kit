title: Generic
description: How to point the kit at any project by declaring locale directories, how layers are named, and how the file format is inferred.

The generic adapter runs any project whose locale files you can name: Svelte, Astro, Rails, a design system package, a monorepo of shared catalogs, or a framework the kit has never heard of. You declare the paths; it resolves the locales. This page covers what it needs, what it does with it, and where it stops.

A **layer** is a scoped locale directory: a Nuxt layer, a workspace package, a shared UI library, or one app in a monorepo. The generic adapter is the one place where you name the layers yourself, one per path.

::note
This is not the fallback the others fall through to. It scores higher than every framework adapter, so declaring `localeDirs` and `defaultLocale` on a Next.js or Vue project deliberately takes the project away from that adapter — see [Detection](/frameworks/detection).
::

## How Detection Recognizes the Project

| Signal | Score |
|---|---|
| Both `localeDirs` and `defaultLocale` declared in your project config | 10 |
| Anything less | 0 |

Ten is the highest score any adapter reaches, and on the one tie possible — a Next.js project with every signal present — registration order still resolves it to `generic`. There is no partial credit: one of the two keys without the other scores nothing, because the adapter cannot resolve without both.

Configuration is read from `i18n-kit.config.ts` (also `.mts`, `.js`, `.mjs`, `.cjs`) and `.i18n-mcp.json`, looked up from the project directory upwards.

## Locale Directories Probed

None are probed. Exactly the paths in `localeDirs` are used, resolved against the project directory. A path that does not exist is an error naming it, rather than a silently empty result.

Each entry is either a string or an object carrying its own layer name:

```ts [i18n-kit.config.ts]
import { defineI18nKitConfig } from '@the-i18n-kit/cli/config'

export default defineI18nKitConfig({
  defaultLocale: 'en',
  localeDirs: [
    'apps/web/locales',
    { path: 'packages/ui/locales', layer: 'ui' },
    { path: 'packages/emails/locales', layer: 'emails' },
  ],
})
```

The same shape works in `.i18n-mcp.json`:

```json [.i18n-mcp.json]
{
  "defaultLocale": "en",
  "localeDirs": [
    "apps/web/locales",
    { "path": "packages/ui/locales", "layer": "ui" }
  ]
}
```

## What Is Derived, and From Which File

Nothing is executed and no framework file is read. Everything comes from your declaration and from the directories themselves:

| Value | Source |
|---|---|
| Locale directories and layer names | `localeDirs` |
| Default locale, and the fallback locale derived from it | `defaultLocale` |
| Locale codes | `locales` when you declare it; otherwise the file names and subdirectory names found across every locale directory |
| File format | Inferred from the **first** locale directory |

Format inference reads the first directory in order: a `.json` file in it means `json`; a `.php` file means `php-array`; failing both, the first subdirectory holding files of either type decides. An unreadable directory yields `json`.

When discovering codes, `index`, `readme`, `config`, `vendor`, `node_modules`, `.git`, `.DS_Store` and dot-entries are skipped, so a `README.md` beside your catalogs is not a locale. Flat files contribute their base name; subdirectories contribute their own name when they hold files in the inferred format.

## Layers

One layer per entry in `localeDirs`. A string entry is named `default`; an object entry takes the `layer` you gave it. Those names are what `--layer` accepts and what per-layer reports are keyed by, so they are worth choosing deliberately — they are the vocabulary you will read in every report afterwards.

## Overrides

The adapter *is* the override. Beyond the two required keys:

| What you want | How |
|---|---|
| A fixed locale list instead of discovery | `locales` |
| Pin the adapter, so a later dependency change cannot move the project | `framework: 'generic'` |
| Authoring context for translation | `context`, `glossary`, `localeNotes`, `translationPrompt` |

## Limits

- `localeFileFormat` in your project config is honored by the [Laravel adapter](/frameworks/laravel), not by this one. The generic adapter infers the format from the first locale directory, so a set of directories in mixed formats resolves as whatever the first one looks like.
- Locale codes are discovered per directory and unioned. A code present in one directory and absent from another is reported as missing there, which is the point — but it does mean a directory holding a deliberate subset of locales needs `locales` declared to describe the intended set.
- Paths are resolved against the project directory. Commit relative paths; an absolute path in a committed config works for its author only.
