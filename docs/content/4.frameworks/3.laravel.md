The Laravel adapter reads `lang/` in either of the two layouts Laravel supports — PHP arrays per namespace, or flat JSON — and takes the default and fallback locale from `config/app.php`.

A **layer** is a scoped locale directory: a Nuxt layer, a workspace package, a shared UI library, or one app in a monorepo. A Laravel project resolves as a single layer named `root`.

A project is recognized as Laravel by an `artisan` file, `laravel/framework` in `composer.json`, or a lang directory holding locale content. A missing or malformed `composer.json` contributes nothing rather than failing.

## Locale Directories Probed

Two candidates, first match wins:

1. `lang/` — Laravel 9 and later
2. `resources/lang/` — earlier versions

Whichever exists becomes the single locale directory. Nothing else is probed, and there is no per-package scan: a Laravel project is one directory of translations as far as this adapter is concerned.

If neither exists, the command fails naming both paths.

## What Is Derived, and From Which File

| Source | Gives | How it is read |
|---|---|---|
| `config/app.php` | `locale` → the default locale; `fallback_locale` → the fallback; a `locales` array, if present, merged with the codes found on disk | Text, matched by pattern — the file is never executed |
| The locale directory | The locale codes: subdirectory names holding `.php` files, or the base names of `.json` files | Directory listing |

Both `'locale' => 'de'` and `'locale' => env('APP_LOCALE', 'de')` are read; in the `env()` form the fallback argument is taken, since that is the value that holds when the variable is unset. `fallback_locale` defaults to the default locale when absent, and the default locale defaults to `en` when `config/app.php` cannot be read at all.

Codes declared in `config/app.php` but absent from disk are kept in the locale list, so a locale you have configured but not yet scaffolded still shows up as missing rather than disappearing.

### File Format

| On disk | Format |
|---|---|
| Subdirectories containing `.php` files (`lang/en/messages.php`) | `php-array` |
| `lang/en.json`, `lang/de.json` or `lang/fr.json` at the top level | `json` |
| Both | `php-array` |
| Neither | `php-array` |

## Layers

One, named `root`, covering the whole project. Nothing in a Laravel layout maps onto scoped locale directories, so app-scoped usage evidence has a single app named `root`.

## Overrides

| What you want | How |
|---|---|
| Pin the file format instead of inferring it | `localeFileFormat: 'json'` or `'php-array'` |
| Restrict or reorder the locale list | `locales` |
| Force this adapter | `framework: 'laravel'` |
| Locale directories elsewhere entirely | `localeDirs` + `defaultLocale`, which hands the project to the [generic adapter](/frameworks/generic) |

```json [.i18n-mcp.json]
{
  "framework": "laravel",
  "localeFileFormat": "json",
  "locales": ["en", "de", "nl"]
}
```

::warning
A `defaultLocale` you declare is **not** consulted by this adapter. The default locale comes from `config/app.php`. Declaring `localeDirs` and `defaultLocale` together is a different thing: it scores the generic adapter above every framework adapter and takes the project away from this one entirely.
::

## Limits

- `config/app.php` is pattern-matched, not evaluated. A locale assembled at runtime, or an `env('APP_LOCALE')` call with no literal fallback, is invisible — the adapter falls back to `en`. Declare `locales` if the list matters and the file does not state it plainly.
- A `vendor/` subdirectory inside the lang directory is skipped when discovering locale codes, so package translations are not mistaken for locales.
- Only one lang directory is used. Translations split across several packages need the generic adapter, where each path can carry its own layer name.
